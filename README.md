# GoodMem Claude Code Plugin

A Claude Code plugin for [GoodMem](https://docs.goodmem.ai) — memory infrastructure for AI agents.

With this plugin, you can operate GoodMem's memory infrastructure in plain English — create and manage embedders, rerankers, and LLMs, ingest memories from files, base64 strings, and plain text, and build knowledge-powered agents for RAG and Deep Research. Also includes Python and Java SDK references for writing GoodMem code.

## Use cases

- **Deep Research agent** — Create an embedder and space, ingest research papers and documents, then ask complex questions that retrieve and synthesize information across your entire knowledge base.
- **RAG pipeline** — Configure embedders, rerankers, and LLMs, store source materials as memories, and retrieve relevant context for answering questions.
- **Self-improving support agent** — Ingest historical issue tickets and resolutions, search for solutions matching a new problem description, and iteratively store new discoveries and fixes as memories so future troubleshooting gets smarter over time.

## Installation

**From the community marketplace** (preferred):

```
/plugin marketplace add anthropics/claude-plugins-community
/plugin install goodmem@claude-community
```

**From this repo** (fallback — use only if the community marketplace is unavailable):

```
/plugin marketplace add PAIR-Systems-Inc/goodmem-claude-code-plugin
/plugin install goodmem@goodmem-plugins
```

## Connecting

The plugin ships two MCP servers. Use either or both.

| Server | Connects to | What the LLM can do | Setup |
|--------|-------------|---------------------|-------|
| `goodmem` | Your own GoodMem instance, local or remote | Everything: search and read memories, and full control over spaces, memories, models, users, and API keys | Base URL and `gm_` API key, from chat or environment variables |
| `goodmem-gateway` | Your instance on GoodMem Cloud | Search and read, save memories, save documents by URL, delete memories, create and rename spaces. Model setup and administration stay in the Cloud console | Browser sign-in — requires a GoodMem Cloud account with an instance |

### `goodmem` — your own instance (all tools)

Runs `npx @pairsystems/goodmem-mcp`, the [GoodMem MCP server](https://www.npmjs.com/package/@pairsystems/goodmem-mcp), which exposes the full GoodMem API as tools. Give it a server URL and a `gm_` API key in either of two ways:

**From chat** (lasts for the session): tell Claude your server details and it calls `goodmem_configure`.

```
> "Configure GoodMem with base URL http://localhost:8080 and API key gm_abc123"
```

Call it again anytime to switch servers.

**Environment variables** (persist across sessions): export before launching Claude Code.

```bash
export GOODMEM_BASE_URL="https://your-server.example.com"
export GOODMEM_API_KEY="gm_..."
```

### `goodmem-gateway` — GoodMem Cloud

Connects to your GoodMem Cloud instance through PAIR's hosted gateway. You need a GoodMem Cloud account with an instance — there is no API key or URL to enter.

1. Run `/mcp` inside Claude Code, select **goodmem-gateway**, and choose **Authenticate**.
2. Sign in on the GoodMem page that opens in your browser and choose your instance.
3. The server shows as connected. Claude Code stores and refreshes the token, so this is a one-time step per machine.

The gateway is intended for single-owner instances until per-user identity is supported. Gateway calls currently act with the instance's root authority rather than applying the signed-in user's individual GoodMem permissions, so every user who connects to an instance through the gateway has the same privileges on it, and the instance's audit records attribute their actions to the root user. Per-user identity is tracked in [goodmem-cloud-provisioning#5455](https://github.com/PAIR-Systems-Inc/goodmem-cloud-provisioning/issues/5455).

To switch instances or sign out, run `/mcp` → **goodmem-gateway** → **Clear authentication**, then sign in again. Spaces can be created and renamed through the gateway, but deleting a space is done in the GoodMem Cloud console. Embedders, rerankers, and LLMs for a cloud instance are set up there too; Claude gives you a one-time link when one is needed. Searches are reranked automatically with the first reranker on your instance, and Claude can ask for an answer generated by the first LLM on it.

### TLS certificates

- **Localhost:** run the server with TLS disabled and connect over `http://localhost:8080`. New installs: `goodmem system install --tls-disabled`. Existing installs: set `GOODMEM_TLS_DISABLED=true` in the server's environment and restart it.
- **Remote server with a private or self-signed CA:** export `NODE_EXTRA_CA_CERTS` with the absolute path of the CA's PEM file before launching Claude Code, and restart Claude Code after changing it.
- An expired or invalid server certificate must be fixed on the server.

## Reloading after updates

After installing a new version or pulling the latest changes, run `/reload-plugins` inside Claude Code to pick up the updates without restarting. If you are using the plugin from this repo, you can run `git pull` to get the latest changes.

### MCP tools

The `goodmem` server exposes all GoodMem API operations as tools:

- **goodmem_configure** — set server credentials from chat
- **goodmem_lookup_model** — look up model info from the built-in registry
- **embedders** — create, list, get, update, delete embedding models
- **llms** — create, list, get, update, delete LLM configurations
- **rerankers** — create, list, get, update, delete reranker models
- **spaces** — create, list, get, update, delete memory spaces
- **memories** — create, list, get, update, delete, retrieve (with optional reranking and LLM answers), batch operations
- **ocr** — extract text from documents
- **users, apikeys, system, admin** — manage users, API keys, server

### Auto-inference

When creating embedders, LLMs, or rerankers, just provide `model_identifier` and the plugin auto-fills provider, endpoint, dimensions, and other fields from the built-in model registry. You only need to provide `display_name`, `model_identifier`, and credentials — everything else is inferred.

Explicit values always override inferred defaults.

### Credential validation

SaaS providers (OpenAI, Cohere, Voyage, Jina, and OpenAI-compatible endpoints for Anthropic, Google, Mistral) require API credentials. If you create an embedder, LLM, or reranker pointing at a known SaaS hostname without providing credentials, the plugin raises a clear error before the request reaches the server. Pass `credentials` (MCP), `api_key` (Python SDK), or the provider API key overload (Java SDK) to proceed.
